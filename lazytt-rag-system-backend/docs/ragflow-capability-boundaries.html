01 · 一句话边界

引擎与产品层的分工

同一个用户动作通常会跨越两套系统。判断“谁负责”时，要区分谁定义业务规则、谁执行底层引擎动作。

LazyTT Gateway

定义对外契约和业务规则。决定谁能看什么、如何检索、怎样排序、是否缓存、如何更新版本、答案能否返回。

＋
RAGFlow Engine

执行文档解析与底层检索。负责 OCR、版面、表格、基础切块、Embedding 写入，以及 Elasticsearch 中的向量/BM25 召回。

＝
当前完整 RAG 系统

用户只调用 Gateway。Gateway 通过 Docker 内网和官方 API 调用 RAGFlow，最终将底层能力包装成稳定的产品服务。

“直接使用 RAGFlow”不等于用户直接调用 RAGFlow。 正常业务流量进入 :8080 Gateway；RAGFlow Server 的内部 API 由 Gateway/Worker 调用，管理界面 :8081 只用于本地运维。
02 · 两条主链路

文件入库和问题回答

每个节点的颜色就是责任归属。琥珀色节点表示业务规则在 Gateway、实际解析或检索动作在 RAGFlow。

文件入库链路
自研API 与共享 Scope校验 X-Tenant-ID、X-User-ID、TENANT/SYSTEM 归属和幂等键
→
自研上传预检MIME、大小、SHA-256 精确去重、暂存
→
自研文档级 Profile 选择显式值优先；兼容默认值优先；Parser/Chunk 按文件类型自动选择
→
组合文档摄取Worker 发起任务，RAGFlow 解析、切块、Embedding
→
RAGFlow底层索引真实 Chunk、向量索引和 BM25 写入 ES
→
自研侧车预索引Summary、Section、Parent、Table、Entity
→
自研READY同步 Job、文档状态，知识库 Revision +1

原始证据 Chunk 始终来自 RAGFlow；侧车索引只做导航，命中后必须回读真实 Chunk。

在线问答链路
自研边界校验TENANT/SYSTEM 可读范围、KB Revision、Document IDs、Metadata
→
自研QueryPlan语言识别、双语 Rewrite、问题分类、动态 Top-K
→
组合多路召回RAGFlow 向量/BM25 + Gateway 侧车路线
→
自研融合与后处理加权 RRF、近重复删除、相邻 Chunk 合并
→
自研可选 Rerank独立 Cross-Encoder；失败回退 RRF
→
自研LLM 回答Token 预算、JSON/SSE、指定响应语言
→
自研引用与缓存引用验证、精确/语义缓存、边界复验

RAGFlow 不负责最终答案生成；最终 LLM、引用校验、缓存和拒答都由 Gateway 控制。

05 · 数据与基础设施归属

数据实际存在哪里

运行服务与存储服务已经拆成两个独立 Compose Project。PostgreSQL 合并为一个物理服务，但 App 与 RAGFlow 仍使用不同数据库、不同账号；以下“归属”表示哪套系统的数据模型在使用它。

LazyTT 应用侧

自研业务数据

  • 共享 PostgreSQL / rag_app：使用独立应用账号，保存逻辑知识库、文档、版本、Job、Revision、侧车索引、查询、引用和反馈。
  • 统一 Redis Stack DB 2：Worker/Scheduler 异步任务和短状态。
  • 统一 Redis Stack DB 0：精确答案缓存和语义缓存 HNSW 向量索引。
  • 上传暂存卷：Worker 消费前的文件。
RAGFlow 子系统

引擎数据

  • 共享 PostgreSQL / rag_flow：使用独立 RAGFlow 账号，保存 Dataset、物理文档、解析任务和模型配置。
  • Elasticsearch：真实 Chunk 正文、Embedding 向量和 BM25 倒排索引。
  • MinIO：RAGFlow 管理的原始文件对象。
  • 统一 Redis Stack DB 1：RAGFlow 内部任务队列、锁和临时状态。
06 · 容易误解的边界

RAGFlow 有，但当前没有直接启用

项目 Profile 明确关闭以下 RAGFlow 内置增强能力。页面中出现相似名词时，实际是 Gateway 自研侧车方案，不应误认为已经启用 RAGFlow 对应功能。

内置 Raptor / GraphRAG

  • use_raptor: false
  • use_graphrag: false
  • use_kg: false
  • 当前“实体关系”只是轻量导航，不是完整知识图谱推理。

内置 Parent-Child / TOC Enhance

  • use_parent_child: false
  • toc_enhance: false
  • 当前 Parent、Section、Summary 和 Table Parent 存在 App PostgreSQL，是 Gateway 侧车索引。

RAGFlow 最终回答

  • 当前没有让 RAGFlow Chat/Assistant 生成最终答案。
  • Gateway 使用自己的 LLM Port 完成 Query Rewrite、回答、SSE 和引用修复。

RAGFlow 内置 Rerank

  • 当前 Rerank 由 Gateway 的独立 RerankPort 调用兼容服务。
  • 未启用或调用失败时稳定回退向量 + BM25 + 侧车 + 加权 RRF。

最终判断标准

凡是“解析原文件、生成真实 Chunk、写入 Embedding/BM25 索引、执行底层召回”，主要属于 RAGFlow；凡是“共享访问边界、业务状态、检索策略、排序融合、答案、引用、缓存和安全更新”，主要属于 LazyTT 自研 Gateway。跨越两边的上传、检索和版本更新属于组合能力。
