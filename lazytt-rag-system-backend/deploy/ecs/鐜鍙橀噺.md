# ECS 环境变量

持久配置唯一来源：`/etc/lazytt/rag.env`（`root:root 0600`），模板见 [.env.dev.example](.env.dev.example)。
每次操作先 `set +x`，再 `bash -n /etc/lazytt/rag.env` 和 `source /etc/lazytt/rag.env`。改配置后重新 release 重建容器；restart 不会重新载入环境。

模板是 Bash `export` 格式，不传给 Compose 的 `--env-file`。URL 密码须百分号编码；拆分密码字段保留原值。不会把整份配置文件挂载进容器。

## 阶段和配置要求

- `build` 不读取 ECS 运行配置。`prepare` 只要求确认 RAGFlow digest，数据库和模型字段可尚未填写。
- `migrate` 只读取目标数据库配置；rag_app 使用 APP_DATABASE_DSN，rag_flow 使用五个 RAGFLOW_POSTGRES 字段。
- `init-ragflow` 要求两库已完成 V1.1.0 / v0.26.4 结构与权限，并填全 PostgreSQL、Redis Stack、ES、MinIO。
- 首次注册时 RAGFLOW_REGISTER_ENABLED 临时设为 1；账号创建后设回 0，正式 release 重建 RAGFlow。已有账号使用 0。
- `bootstrap-account` 只通过 stdin 接收管理员邮箱/密码；不会把管理员密码长期存入配置。
- `bootstrap-models` 要求已生效 API Key 与 LLM、Embedding、文档 Vision 三元组，真实探测后写回模型引用、维度与 Chat 兼容字段。
- `release` 要求完整运行配置；Rerank、媒体处理关闭时对应可选三元组可以为空。开启媒体时 ASR 和 MEDIA_VISION 独立配置。

## 模型预填值与首次初始化

模板的公开模型端点、模型名、兼容参数、1024 维向量配置及媒体/重排开关，
来自 2026-09-07 本机运行的 Gateway、Worker、Scheduler，三者与本地私有配置一致。
此处只保存非敏感值；各模型 API Key 仍须在 ECS 配置，不能由其他职责隐式复用。
预填的 RAGFlow 模型引用不代表目标 ECS 已登记模型；首次仍须运行 `bootstrap-models`
完成真实端点探测和官方 API 注册，并使用其写回的模型引用、维度与兼容参数。
本机存储使用 Docker Desktop 地址和映射端口，不复制到 ECS 配置。
RAGFlow 镜像使用 `ghcr.io/lazyaix/ragflow` 中经核实的 v0.26.4 amd64 digest；
模板占位符须替换为完整 digest，不能直接填写 tag 或短 IMAGE ID。

## 连接与容量

共享 Store 的实际地址和端口必须能从 ECS 应用 bridge 网络到达；不能填容器内的 127.0.0.1，也不能照抄本地服务名。此拓扑不创建共享 Store 网络。
Redis Stack：DB 0 为语义缓存/RediSearch，DB 1 为 RAGFlow，DB 2 为 Celery。DB 编号不构成安全隔离；专用实例或经审阅 ACL 才能约束共享访问。必须验证 FT 功能。
MinIO 使用 RAG 专用身份/Bucket；ES 使用审阅后的索引权限；具体策略由共享 Store 管理员配置，本仓库不变更其他系统 ACL。
默认 RAGFlow 每进程 PG 池上限 20，自研每进程 pool_size=5/max_overflow=5。Celery 多进程、RAGFlow 多连接池会放大总连接数；按实际进程数和 Store 余量验收，不能只相加三个服务名。

## Gateway 绑定

`RAG_GATEWAY_BIND_HOST` 默认 `127.0.0.1`；显式 `0.0.0.0` 仅开放 Gateway。
公网来源范围须由管理员明确决定，并与主机及云安全组规则一致。该变量不提供认证，
不改变 RAGFlow 的回环绑定。变更通过持久环境配置及正常 release 生效，不能只 restart。

## GitHub 配置

| 类型 | 名称 | 含义 |
|---|---|---|
| Variables | ECS_DEPLOY_ENABLED | 仅设为 `true` 才启用 dev push 自动 release；初次先 build/prepare。 |
| Variables | ECS_HOST / ECS_USER / ECS_PORT | 核实的 SSH 主机、用户、端口（默认 22）；当前脚本要求能读取 root:root 0600 配置及执行 Docker。 |
| Variables | ECS_REPO_DIR | 独立部署绝对路径，如 `/opt/lazytt/lazytt-rag-system`，仅存 Compose/配置模板/回执/锁，不是源码 checkout。 |
| Variables | ECS_ENV_FILE | 默认 `/etc/lazytt/rag.env`。 |
| Secrets | ECS_SSH_PRIVATE_KEY / ECS_KNOWN_HOSTS | 部署 SSH 私钥、经独立核实的主机公钥。保留 StrictHostKeyChecking。 |
| 内置 | GITHUB_TOKEN | workflow 临时用于 GHCR；确认包的 Actions 权限。不会写入主机应用环境。 |

`build/prepare/release` 是 workflow_dispatch 输入，不新增 ECS_DEPLOY_MODE。手动复用候选必须同时填写 candidate_image（digest）与 candidate_revision（完整 SHA）。工作流文件需已在 GitHub 可触发的分支；本次没有推送或修改默认分支。

## 可选 MinerU 官网 VLM 解析

| 环境变量 | ECS 配置 |
| --- | --- |
| `MINERU_CLOUD_API_TOKEN` | 官网 Token；留空跳过，仅注入适配容器 |
| `MINERU_CLOUD_MODEL` | `vlm` |
| `MINERU_CLOUD_MAX_CONCURRENCY` | `10`，云端请求并发上限 |
| `MINERU_CLOUD_RESULT_CONCURRENCY` | `2`，结果下载与转换并发上限 |

完整启用、停用及验收步骤见 [ECS 操作入口](README.md#可选-mineru-官网-vlm-解析)。
