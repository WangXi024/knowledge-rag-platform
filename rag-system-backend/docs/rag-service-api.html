当前是Direct Tenant/User开发联调模式

除健康、版本和能力接口外，业务请求必须同时携带X-Tenant-ID和X-User-ID。Tenant ID决定可访问的租户共享范围，User ID保留调用主体、审计、缓存和幂等边界；两个Header都不会证明调用者真正拥有该身份，因此禁止把当前模式直接暴露到公网或不受信网络。

Header是否必填用途示例
X-Tenant-ID业务接口必填确定TENANT共享范围；建议使用Identity不可变租户主键identity-tenant-123
X-User-ID业务接口必填标识调用主体，用于审计、缓存和幂等；不形成个人知识库范围identity-user-123
Idempotency-Key部分写操作必填防止网络重试重复创建资源或任务create-kb-001
X-Request-ID可选调用链追踪；不传时由Gateway生成UUID
Authorization当前不使用预留给未来Identity JWT + JWKS方案—

错误类型与错误上下文

error.code是程序判断依据；retryable决定是否有限重试；details提供字段名和失败原因；中文message只用于展示。

字段含义调用方处理
request_id本次调用追踪UUID日志和缺陷单必须保留
error.code稳定机器错误码使用该字段分支处理
error.message面向人的错误描述可以展示，不能作为程序判断条件
error.retryable稍后重试是否可能成功仅true时有限重试，不能无限循环
error.details字段、原因等上下文用于定位具体输入问题

MCP Server调用规则

  1. 从Identity或可信MCP会话取得稳定Tenant ID与User ID，不允许LLM自由填写。
  2. 只调用RAG Gateway :8080，不要直接连接RAGFlow或数据库。
  3. 每个业务请求自动添加X-Tenant-ID与X-User-ID。
  4. 管理端创建TENANT或SYSTEM共享知识库；问答默认检索当前租户可访问的全部共享库。
  5. 写操作生成并复用Idempotency-Key；上传后轮询Job直到文档READY。
  6. 保留Gateway返回的request_id、引用、warning和完整错误对象。
