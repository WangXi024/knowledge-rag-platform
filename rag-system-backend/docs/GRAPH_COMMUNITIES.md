# 图谱浏览、社区摘要与多来源契约

本文说明第二期的实现及操作边界。固定使用官方 RAGFlow `v0.26.4`，不修改、Fork
或补丁上游，不新增外部图数据库。本文不宣称数据库迁移、真实报告生成、前后端
联调、内容删除/恢复或业务质量验收已经完成；验收结论必须附独立脱敏记录。

## 1. 原生结构与本平台报告的归属

RAGFlow 负责实体和关系抽取。Gateway 从官方图接口读取真实节点名称、类型、描述、
关系端点及文档来源，先校验活动物理文档集合与每个来源，再进行只读浏览。
节点/关系描述属于生成内容，不是原文摘录。

Gateway 在受限图上按无向连通分量划分社区，并从活动文档回读真实 Chunk，使用现有
通用 Chat 模型生成摘要。报告明确带有：

| 字段 | 值或含义 |
| --- | --- |
| `origin` | `gateway_generated` |
| `strategy_ref` | `gateway-connected-community@1` |
| `graph_profile_ref` | `native-graph-with-summaries@1` |
| `generator_model_ref` | 实际使用的 Gateway Chat 模型名 |
| `graph_generation` / `content_revision` | 报告依赖的图代数与内容修订 |
| `configuration_version` | 当前可用配置的发布边界 |
| `sources` | 真实原文、文档/Chunk 定位与活动版本快照 |

这里的社区不是原生 Leiden 编号，摘要不是 RAGFlow 的 `community_report`。原生
Graph Chat 只用于构图；Gateway 报告阶段使用现有通用 Chat 配置。GET 浏览、展开、
查看报告和问答读取已有报告都不生成新社区报告，也不触发构图。

## 3. 策略与构建生命周期

| Graph Profile | 原生参数 | Gateway 报告 |
| --- | --- | --- |
| `native-graph-light@1` | light；community/resolution 为 false | 无，既有语义不变 |
| `native-graph-with-summaries@1` | 与上述原生参数相同 | 构图后增加受控生成阶段 |

配置仍使用既有知识库 Graph 配置入口。切换到新策略会使旧构图失效，需要按已有
Job 流程构建；自动构建受 `auto_build` 控制。启用摘要策略意味着构建任务可能增加
Gateway Chat 调用，单纯浏览和切换查询开关不会生成摘要。

构建顺序为：原生任务完成 → 严格原生来源验收 → 复读内容/行版本 → 生成或恢复
已知报告 → 再次核对原文与原生来源 → 保留原行版本 CAS 发布 READY。内容已经
落后时不生成报告、不发布旧图；自动构建开启时只安排最新后继任务。来源异常且
无法证明内容过时则失败封闭。已完成的旧 light 图不会自动获得报告。

每次模型调用前独立提交费用意图；收到可靠结果后保存可恢复结果。进程中断或响应
未知时保留意图，报 `RAG-GRAPH-026`，不能自动重发收费调用。纯查询开关改变时，
同图、同内容、同策略和同来源指纹的结果可复用并对齐发布配置版本。策略/内容变化
不能借旧报告绕过重建。缺少报告构建器时，新策略不能发布为 READY。

原生重建、清理与取消仍遵守一期规则：只清已知终态任务对应的派生图，原文保留；
提交恢复不重复 POST；取消使用 `wipe=false`。任务记录缺失不等于执行器终止，
也不表示模型已停止计费。详见 [一期生命周期说明](NATIVE_GRAPHRAG.md)。

## 4. 读取与生成预算

| 阶段 | 固定上限与超限行为 |
| --- | --- |
| 官方图/单次原文分页响应 | 解码前流式读取最多 4 MiB；声明长度超限提前拒绝 |
| 原生完整性 | 节点数必须小于 256、边数小于 128；达到官方裁剪界限即拒绝 |
| 一次完整原文回溯 | 最多 8 份文档，每文档最多 100 个完整 Chunk；总数与实际返回必须一致 |
| 原文正文 | 单块最多 32,768 字符；全部来源最多 262,144 字符；超限 `RAG-GRAPH-012` |
| 报告生成 | 最多 4 份报告；每报告至多 12 条、每条至多 2,000 字符的连续原文摘录 |
| 报告支撑 | 至少两份不同活动文档、至少两个不同真实 Chunk；单文档社区不能充当多来源报告 |
| 管理浏览 | 总预算 8 秒，至多 40 节点、80 条关系，最多两跳 |
| 在线报告读取 | 总预算 8 秒，最多两个知识库、四份可用报告 |
| 持久报告/回答聚合集合 | 最多四份，JSONB 载荷最多 1 MiB |

前置原文回读完整性与后续有限上下文选择是不同步骤：前者不能截掉尾部后声称
完整覆盖，后者只使用选中的真实连续原文。返回来源不是文档指针占位符，每条均
带逐字 quote、文档修订、活动版本、引擎文档/Chunk 绑定及 SHA-256。TXT/Markdown
的占位页码/坐标被清空，不能把它们显示成物理页码。

## 5. 只读管理 API 与界面

以下路径均位于 `/v1/management/knowledge-bases/{knowledge_base_id}/graph`：

| GET 路径 | 参数及用途 |
| --- | --- |
| `/view` | `query` 搜索；`node_id` 展开；`depth=0..2`、`limit=1..40`、`generation` 固定代数 |
| `/communities` | 列出已生成、当前就绪且来源有效的报告；可携带 `generation` |
| `/communities/{community_id}` | 同版本报告详情及多来源；可携带 `generation` |

所有入口先完成管理访问与知识库资源授权；不可见与不存在保持统一 404。节点和边
使用按知识库/图代数生成的公开定位 ID，客户端不能提交任意引擎 Dataset、源文档 ID
或任意遍历参数。重建后应重新加载，不能沿用旧邻域。只读服务会再次核对内容/图
状态和每条原文，失效、超限或无法回溯时不返回旧报告。

管理界面区分“实体与关系”和“社区摘要”，可查看实体类型、生成描述、邻域和原文。
描述区域明确标记生成属性；来源不可用时显示说明。来源预览是有限摘录，查看完整
上下文通过已有文档 Chunk 接口，并继续携带文档修订，避免活动版本切换后误读。
图谱不可用或已过期时停止展示旧结构，原文业务路径继续受原有授权与版本规则保护。

## 6. 问答与独立聚合证据

问答 JSON/SSE 请求默认 `evidence_mode="original"`。显式传入
`evidence_mode="community"` 才选择 `rag-answer-community-localized@1` 提示词，
使用已有报告与原文组织回答。原文引用 `[C1]` 与聚合引用 `[A1]` 分开：

- `citations` 保存真实原文引用，不能塞入摘要正文。
- `aggregate_evidence` 保存明确归属 Gateway 的报告，以及至少两份原文来源。
- SSE 通过 `aggregate.evidence` 独立发布报告；`completed` 携带最终证据集合。
- 社区模式等完整生成、标签和实时来源复验成功后才发布正文；原文模式保留既有
  增量流式行为。验证失败不提前流出未经核验的社区答案。

无可用报告、原生图超限、策略未启用或预算耗尽时，社区模式返回无证据及明确
warning，不假装已经成功使用社区聚合。生成后原文变化会拒绝该次派生回答。用户
需要普通问答时可选择原文模式。社区摘要不支持元数据过滤；有过滤条件时不会用
未过滤的全库摘要补答。

精确/语义缓存包含证据模式、聚合提示词、图代数、内容/配置版本、报告正文摘要
和来源指纹。命中后仍核对活动文档、原文及当前报告；关闭图谱、策略切换、重建或
内容变更后不允许旧摘要越过边界。历史回答可以保留生成时的证据快照，不能把历史
快照当作当前仍有效的报告。

## 7. 数据迁移、验收与限制

应用 Schema `V1.3.0` 在 `V1.2.0` 基线上增加图谱报告 JSONB，以及查询记录的证据
模式、聚合策略和报告快照字段；不改变历史 `citation_record`。历史问答默认原文模式，
历史图谱报告为空。迁移前应保留可验证备份，外部数据库继续由 DBA 执行审核 SQL；
失败时保留现场，不通过清表、改校验和或手工伪造版本号绕过启动门禁。

用独立合成知识库顺序验收：旧策略普通检索 → 新策略单次构建与费用意图 → 实体/
关系搜索与展开 → 两文档报告逐来源回读 → JSON/SSE 的 C/A 标签 → 缓存命中复验
→ 删除、版本切换、查询开关、取消和 Worker 恢复。跨租户访问应保持不可见；系统
共享库按其明确授权另验。单文档、超图规模、超来源预算、无可用报告和模型结果未知
均应记录明确失败或不可用状态。低内存环境一次只运行一个测试/构建进程。

当前管理授权仍依赖项目现有内部网络信任策略，不新增生产管理员/成员 ACL。节点
抽取和模型摘要仍可能有误，来源存在只证明可回溯，不能替代事实质量评价。受官方图
裁剪和本期预算限制，本功能不承诺大库全图遍历、任意关系推理、生产吞吐或收益提升。
最终启用范围应由独立真实验收与业务黄金集结果决定。
