## 实现范围

- 管理端支持有限图谱浏览、实体搜索、节点与关系详情、邻域展开和带文档修订的原文跳转。
- 新增不可变策略 `native-graph-with-summaries@1`，保留 `native-graph-light@1` 原行为。
- v0.26.4 未提供满足精确多来源回溯要求的公开原生社区报告接口，本期在 Gateway 中
  按原生图的连通分量生成社区摘要，来源为当前有效的真实原文 Chunk。返回值明确标记
  `origin=gateway_generated`、模型和 `gateway-connected-community@1` 策略，不冒充原生报告。
- 问答默认原文模式；社区模式显式选择，`[A1]` 聚合证据与 `[C1]` 原文引用独立持久化、
  发布和展示。聚合引用必须关联至少两份文档，不制造 Chunk、页码或坐标。
- 社区 SSE 完成来源复验后发布，事件名为 `aggregate.evidence`；原文模式维持增量输出。
- Schema V1.3.0 与 Redis 语义缓存 v4 扩展证据模式和聚合来源边界，旧普通问答兼容。

## 真实集成验收

使用独立合成租户、知识库及两份 TXT 文档，不使用用户知识数据。官方 API 与单个原生
执行器分段运行；不同时驻留、不并发收费、不改上游源码或数据库任务记录。

本次初次构图返回 12 个节点、29 条关系；一个 Gateway 摘要关联两份文档的两个真实
Chunk。浏览、搜索、一跳邻域、三条浏览入口跨租户 404、过期图代 409、非法预算 400
及带文档修订的逐字来源回读通过。浏览期间图状态未改变。

构图代理观察到 6 次串行 Graph Chat 请求，均 HTTP 200，实际响应 usage 合计
24,741 tokens；另一次 Gateway 摘要生成 HTTP 200，耗时约 8.453 秒、639 tokens。
两种口径分列，不代表完整链路费用或货币成本。一次构图中内存快照为原生执行器约
1.064 GiB、ES 504.3 MiB、MinIO 82.5 MiB、PostgreSQL 70.79 MiB、Redis 12.82 MiB、
代理 16.52 MiB；只是该时刻观测，不是峰值、宿主机总内存或生产容量结论。

首次入库被验收观察器误把原文件二进制响应解码为 JSON 中断；修正观察器后经正式

## 已知限制

- 这是 Gateway 社区策略，不是 RAGFlow 原生 Leiden 社区或原生社区报告直通。
- 图读取、社区数量、来源文档/Chunk、摘录长度和模型上下文均有严格上限；超限明确
  不可用，不宣称支持大库全图遍历。详细预算见 [GRAPH_COMMUNITIES.md](GRAPH_COMMUNITIES.md)。
- 社区模式不支持 Metadata 过滤；带过滤条件时明确返回无聚合证据。无有效社区摘要时
  提示选择原文模式，不能静默把普通原文答案伪装成社区回答。
- 模型生成事实质量仍需业务黄金集评估；可逐字回溯仅证明来源存在。未进行生产负载、
  大规模成本评估或本期音视频验收。管理权限沿用项目现有内部网络信任策略。
- 真实测试仅覆盖记录的合成案例；单元/契约用例中的故障注入不等同于真实故障演练。
