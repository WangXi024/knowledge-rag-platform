# 数据库设计

本规格描述应用事实与隔离约束。详细 SQL、迁移前提和验收入口见
[当前数据库部署](../../deploy/ecs/README.md)、
[Schema 发布记录](../../docs/database-deployment-package/RAG_APP_SCHEMA_RELEASES.md)。
ORM 定义在 `infrastructure/postgres/models.py`、`graph_models.py`；启动门禁在
`bootstrap/database_schema.py`。

## 1. 数据库归属

PostgreSQL `18.4` 中，应用使用独立 `rag_app` Database/Schema/账号；RAGFlow 使用
独立 `rag_flow` Database/账号。两侧迁移、备份、权限及连接分别管理；应用不得通过
读取 RAGFlow 内表或索引实现功能，只使用公开 HTTP API。

当前应用发布基线为 `V1.2.0 / 0007_native_graphrag`，精确表集合共 **14 张**，包括
版本表；不是通过“至少存在这些表”猜测兼容。只读结构门禁还核验版本、checksum、
Schema/对象所有权与权限边界。具体 Owner、运行角色和权限按部署 SQL 建立，不在
文档中填写真实密码或连接串。

## 2. 应用表清单

| 表 | 事实与用途 |
| --- | --- |
| `alembic_version` | 冻结演进头、正式发布版本、checksum 和应用时间 |
| `config_profile` | 不可变名称/版本配置、启用状态和内容摘要 |
| `knowledge_base` | TENANT/SYSTEM 资源归属、引擎映射及内容 revision |
| `document_record` | 活动文档主记录、活动版本映射、解析状态和统计 |
| `document_version` | 候选/活动/退役版本、独立物理文档映射及更新结果 |
| `document_index_node` | Summary/Section/Parent 等可重建侧车导航 |
| `document_entity` | 确定性轻量实体导航 |
| `entity_relation` | 显式关系侧车索引，不替代原生图谱 |
| `ingestion_job` | 包括 GRAPH_BUILD 的持久化任务、尝试次数、租约、检查点与结果 |
| `idempotency_record` | 调用主体范围内请求指纹、幂等键与结果快照 |
| `query_record` | 调用主体的查询/回答审计、结果及警告 |
| `citation_record` | 经校验的原文引用与请求关联 |

| `graph_state` | 知识库图谱配置、状态、版本、代数、任务指针和错误；不存模型密钥或图谱正文 |

## 3. 所有权与一致性

资源表按 `security_scope_id` 查询，组合唯一键/外键阻止文档、Job 和图谱跨 Scope
指向其他知识库。TENANT 资源同租户共享，SYSTEM 资源按系统共享策略读取；审计、
幂等与缓存仍保留调用主体范围，不能因读取共享库而共享调用历史。

`graph_state` 以 `(security_scope_id, knowledge_base_id)` 为复合主键，用 `row_version`
进行乐观并发控制；内容 revision、目标/已构建 revision、configuration_version 与
graph_generation 分开记录。数据库限制同一资源知识库只能有一项在途 GRAPH_BUILD。
任务状态与图谱占用在同一事务提交，Worker 丢失租约必须回滚并停止写回。

图谱全局与知识库默认关闭，迁移不会为旧库自动插入启用记录或发起模型调用。文档
版本发布、删除和回滚使旧图失效；图谱构建不递增内容 revision。Redis 任务消息和
答案缓存不是 PostgreSQL 事实的替代，丢失缓存不等于丢失文档。

## 4. 迁移与恢复

全新库按冻结 `V1.0.0` 初始化，再顺序执行 `V1.0.0→V1.1.0→V1.2.0`；已有 V1.1.0
执行 `migrations/rag_app/V1.1.0__to__V1.2.0__native_graphrag.sql`。不得修改历史 SQL、
跳过数据前提、手工改版本号，或用清库伪装迁移成功。

`local` 开发入口仅处理代码明确识别的版本链；`external` 由 DBA 执行已评审 SQL，
应用仅只读校验。普通生产启动不代替 DBA 建表。关闭 Graph 是功能回退，不删除
graph_state 或逆向迁移；数据库灾备使用已验证备份及恢复流程。

迁移、Repository 和恢复演练按单任务、并发 `1` 串行安排。最小模型 API 可调用不
证明真实数据库/原生图谱集成已完成；完整流程仍须按验收规范单独记录。临时 Kimi K3
不引入数据库字段、凭据或专用 Token 参数变更。
