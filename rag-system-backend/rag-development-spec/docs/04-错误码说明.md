# 错误码说明

稳定错误由 `src/rag_service/domain/errors.py` 及对应应用服务定义，经 API 层统一映射。
具体字段与 HTTP 响应以[OpenAPI](../openapi/rag-api-v1.yaml)为准。

## 1. 响应与处理原则

普通失败响应包含 `request_id` 和 `error`；错误对象包含 `code`、`message`、`retryable`
及字段级 `details`。参数校验统一为 `400 / RAG-COMMON-001`，不返回原始模型响应、
内部堆栈、密钥或其他范围的资源信息。不可见资源与不存在统一返回对应的 404。

调用方按稳定 code 和 retryable 判断，不通过中文 message 分支。重试必须有上限，
并保留请求/任务身份；涉及写入时遵守接口幂等约定，不能自动换键重复收费动作。
异步请求已经返回 202 后，执行失败记录在 Job/图谱状态中，不会把原响应改成失败码。

| 分类 | 典型错误 | 处理方向 |
| --- | --- | --- |
| `RAG-COMMON-*` | 请求字段、通用资源或未知异常 | 修正输入；未知异常保留 request_id 排查 |
| `RAG-KB-*`、`RAG-DOC-*`、`RAG-JOB-*` | 资源不存在、状态或版本冲突 | 在相同身份与资源范围重新查询，不猜其他 Scope |
| `RAG-CONFIG-*` | Profile、缓存索引、Embedding 或能力预检不兼容 | 修正配置/登记/结构后再试，不修改旧 Profile 绕过 |
| `RAG-RF-001/002/003/004/006` | RAGFlow 连接/业务失败/超时/无效协议/Key 被拒绝 | 按明确 retryable 有限恢复；凭据拒绝不盲试 |
| `RAG-LLM-001/002/003` | Chat 不可用、超时或响应协议无效 | 有限恢复并记录依赖阶段，不伪造答案 |
| `RAG-GRAPH-*` | 原生图谱能力、边界、任务与恢复错误 | 见下表，保留普通检索的独立降级路径 |

以下逐码表只列代码中已声明或实际使用的稳定码，不补造编号空缺。HTTP 是当前抛出
场景的映射，不保证所有接口都会返回该码；Worker 错误也可能只记录在异步任务中。
“是”表示当前领域错误允许有界恢复，不保证下一次成功；同一码存在不同场景时，
以实际响应的 `retryable` 和任务状态为准，不能仅凭表格自动重发写操作。

### 1.1 通用错误与并发一致性

来源：`api/app.py`、`domain/errors.py`、`domain/state.py`、
`application/idempotency.py`、`application/online.py` 与摄取服务。

| 错误码 | HTTP | 领域可重试 | 含义及恢复要求 |
| --- | --- | --- | --- |
| `RAG-COMMON-001` | 400 | 否 | 请求参数、身份 Header、UUID 或重复资源 ID 无效；按 details 修正输入 |
| `RAG-COMMON-004` | 404 | 否 | 通用资源在当前范围不可见或不存在；不揭示其他范围资源 |
| `RAG-COMMON-005` | 409 | 否 | 非法状态转换；重读当前状态，不能强制覆盖 |
| `RAG-COMMON-006` | 413 | 否 | 文件或查询长度超过当前上限；缩小请求，不能原样无限重试 |
| `RAG-COMMON-008` | 409 | 是 | 相同幂等请求仍在处理；等待或查询同一请求，不换键重复提交 |
| `RAG-COMMON-009` | 409 | 否 | 同一幂等键对应了不同请求指纹；核对请求与键的归属 |
| `RAG-COMMON-010` | 409 | 否 | 问答请求已结束，当前取消操作不再适用 |
| `RAG-COMMON-011` | 同步兜底为 500 | 同步兜底为是；异步见任务 | 未分类内部错误，亦用于保存 Worker/查询失败；保留 request_id，不暴露堆栈 |
| `RAG-COMMON-012` | 503 | 是 | 关键依赖导致服务未就绪；核对脱敏依赖状态后有限恢复 |
| `RAG-DB-002` | 409 | 是 | 文档、版本、Job、知识库或映射保存的并发冲突；回滚并重读，不能覆盖新行版本 |

### 1.2 知识库、文档与任务

来源：`application/offline.py`、`application/ingestion_worker.py`、
`application/profiles.py`、`infrastructure/staging/filesystem.py` 及 RAGFlow/媒体适配器。
同一码的详细消息可能定位到不同阶段，尤其不能把解析超时和重复 external_id 视为
相同重试场景。

| 错误码 | HTTP | 领域可重试 | 含义及恢复要求 |
| --- | --- | --- | --- |
| `RAG-KB-001` | 404 | 否 | 知识库不存在、不可见或没有可用知识库；保持当前授权范围查询 |
| `RAG-KB-003` | 409 | 否 | 知识库当前状态不可修改或上传 |
| `RAG-KB-004` | 422 | 否 | 没有兼容该文件类型的 Parser，或显式 Parser 不支持该类型 |
| `RAG-KB-005` | 409 | 否 | 非空知识库删除需要明确 force=true；不能自动升级为强制删除 |
| `RAG-KB-006` | 409 | 是 | 删除知识库 Job 缺少执行依赖；核对任务 payload 与恢复阶段 |
| `RAG-DOC-001` | 404 | 否 | 文档在当前可访问知识库范围不存在或不可见 |
| `RAG-DOC-002` | 415 | 否 | 文件扩展名不在支持范围 |
| `RAG-DOC-003` | 400 / 415 | 否 | 文件名、空内容、元数据、MIME 或文件签名不合法；按实际字段和文件内容修正 |
| `RAG-DOC-004` | 422 | 否 | MinerU 图片包装输入不符合静态 PNG/JPEG、像素或转换大小限制 |
| `RAG-DOC-005` | 409 | 否 | Worker 发现文档当前状态不能上传或解析 |
| `RAG-DOC-006` | 409 | 否 | 当前文档不能执行解析/删除，或切换图片包装策略必须重新上传 |
| `RAG-DOC-007` | 409 | 否 | 重试入口仅允许失败文档 |
| `RAG-DOC-008` | 502 | 按具体响应 | 原生文档/候选解析失败，或没有可发布 Chunk；部分空结果不可自动重试，先核对解析配置 |
| `RAG-DOC-009` | 409 / 504 | 按具体响应 | 409 可为 external_id 重复，504 为普通/候选解析超时；不能对重复资源按超时策略重试 |
| `RAG-DOC-010` | 503 | 是 | 上传暂存卷不可写或容量不足；恢复存储条件后再试 |
| `RAG-DOC-011` | 409 | 是 | 暂存文件缺失、未就绪，或大小/摘要与预期不一致；核对共享卷和文件，不跳过校验 |
| `RAG-DOC-012` | 409 | 否 | 同一范围知识库已有完全相同内容；利用响应指向的已有文档，避免重复入库 |
| `RAG-DOC-013` | 422 / 503 | 按具体响应 | 音视频处理能力未启用、输入/媒体处理或 ASR/媒体 Vision 调用失败；区分不可用与无效输入 |
| `RAG-DOC-014` | 409 | 否 | 新版本与当前活动版本内容完全相同，无需更新 |
| `RAG-DOC-015` | 409 / 503 | 按具体响应 | 版本能力/迁移未就绪、活动或候选映射缺失、暂存缺失或更新 payload/操作无效；按具体阶段处理 |
| `RAG-DOC-016` | 409 | 按具体响应 | 主文档不处于允许更新/回滚的状态；API 与 Worker 场景的恢复标记可能不同 |
| `RAG-DOC-017` | 404 | 否 | 文档版本在当前范围不存在 |
| `RAG-DOC-018` | 409 | 否 | 目标版本不处于可回滚状态，或缺少可用物理文档映射 |
| `RAG-DOC-019` | 409 | 否 | 原文件预览所绑定的版本或解析状态已经变化；刷新列表后重新打开 |
| `RAG-DOC-020` | 415 | 否 | 当前原文件预览仅支持 PDF |
| `RAG-DOC-021` | 404 | 否 | 原文件不可用；不返回其他范围文件或猜测下载目标 |
| `RAG-DOC-022` | 413 | 否 | 原文件大小超出预览允许范围，上限为 100 MiB |
| `RAG-JOB-001` | 404 | 否 | Job 不存在，或其关联知识库对当前调用方不可见 |
| `RAG-JOB-002` | 409 | 否 | Job 当前状态或类型不可执行 |
| `RAG-JOB-003` | 409 | 按具体响应 | 文档已有在途 Job，或上传尚未完成不允许立即删除；先核查现有任务 |
| `RAG-JOB-004` | 409 | 否 | 没有可由重试入口恢复的失败 Job |
| `RAG-JOB-006` | 409 | 否 | Job 已结束，不能再次取消 |
| `RAG-JOB-007` | 409 | 否 | 上游解析已取消；按取消结果收尾，不继续发布成功状态 |

### 1.3 配置、RAGFlow 与模型

来源：`domain/errors.py` 与 `application/profiles.py`。配置问题必须修正其前提，
不能通过修改旧版本 Profile、清库或隐式换模型规避门禁。

| 错误码 | HTTP | 领域可重试 | 含义及恢复要求 |
| --- | --- | --- | --- |
| `RAG-CONFIG-001` | 422 | 否 | 请求的 Profile 不存在或未启用 |
| `RAG-CONFIG-002` | 422 | 否 | Profile Schema、解析路由、模型或检索配置组合不兼容；按具体消息核对受控参数 |
| `RAG-CONFIG-003` | 409 | 否 | 同名同版本 Profile checksum 冲突；新增版本，不能覆盖已导入含义 |
| `RAG-CONFIG-004` | 503 | 否 | 启动所需 Profile 未导入或未启用 |
| `RAG-CONFIG-005` | 503 | 否 | 语义缓存索引字段或向量定义不兼容；按索引版本流程处理 |
| `RAG-CONFIG-006` | 503 | 是 | Embedding 服务不可用 |
| `RAG-CONFIG-007` | 503 | 否 | 实际向量维度与配置/索引契约不一致 |
| `RAG-CONFIG-008` | 502 | 是 | Embedding 响应结构或向量数值无效 |
| `RAG-CONFIG-009` | 503 | 是 | 启用的真实 Rerank 服务启动验证失败；不把错误凭据/协议当成已就绪 |
| `RAG-RF-001` | 503 | 是 | 无法连接 RAGFlow |
| `RAG-RF-002` | 502 | 按具体响应 | RAGFlow HTTP 或业务 Envelope 失败；仅按适配器给出的恢复标记处理 |
| `RAG-RF-003` | 504 | 是 | RAGFlow 请求超时；写入结果可能未知，先按任务/检查点恢复 |
| `RAG-RF-004` | 502 | 是 | RAGFlow JSON、必需字段、类型或协议不合法；不能将无效响应解释为成功 |
| `RAG-RF-006` | 401 | 否 | RAGFlow API Key 被拒绝；修正服务端凭据，不反复尝试 |
| `RAG-RF-007` | 409 | 是 | RAGFlow 外部创建/修改/删除已成功，但本地映射未完成；核对副作用后恢复，避免重复对象 |
| `RAG-LLM-001` | 503 | 是 | Chat 服务不可用或持续返回临时故障 |
| `RAG-LLM-002` | 504 | 是 | Chat 生成超时，保留原请求执行边界 |
| `RAG-LLM-003` | 502 | 是 | Chat 返回内容不符合当前通用协议，不能据此伪造回答 |

## 2. 原生图谱错误

下表 HTTP/retryable 描述领域错误；异步 Worker 会将它写入 Job 并执行有界恢复。
图谱管理 `last_error` 当前投影为 `retryable=false`，不能以这一字段替代 Job 的实际
`RETRY_WAIT`、尝试次数和状态判断。实现入口为 `application/graph.py`、
`application/graph_worker.py`、`infrastructure/ragflow/graph_adapter.py`。

| 错误码 | HTTP | 领域可重试 | 含义及恢复要求 |
| --- | --- | --- | --- |
| `RAG-GRAPH-001` | 409 / 503 | 否 | 知识库状态不可构图，或适配器全局图谱未启用；先核对状态和开关 |
| `RAG-GRAPH-002` | 503 | 否 | 全局能力或已登记 Chat 引用未就绪；完成显式模型准备 |
| `RAG-GRAPH-003` | 409 | 否 | 知识库尚未启用图谱 |
| `RAG-GRAPH-004` | 409 | 否 | 本地 READY 活动记录与上游全部物理文档不严格一致，或没有可构建文档；核查摄取与版本生命周期 |
| `RAG-GRAPH-005` | 409 | 视具体响应 | 状态并发更新可重读后有限重试；任务已被后继替换时不可继续旧任务 |
| `RAG-GRAPH-006` | 409 / 502 | 否 | 原生提交结果或可恢复标识无法确认；先核对上游，不能盲目重复构图 |
| `RAG-GRAPH-007` | 409 | 否 | 当前原生任务被另一构建替换，旧 Worker 不得发布结果 |
| `RAG-GRAPH-008` | 502 | 否 | 上游明确报告构图失败 |
| `RAG-GRAPH-009` | 504 | 是 | 构图轮询超时，上游可能仍运行；恢复同一任务，不新提交 |
| `RAG-GRAPH-010` | 502 | 是 | 原生任务暂时无法确认，有限回读同一任务 |
| `RAG-GRAPH-011` | 504 | 是 | 已请求取消，终止尚未确认；保留 CANCELLING，不能报告已停止调用或计费 |
| `RAG-GRAPH-099` | 500 | 否 | 未分类图谱执行异常；返回稳定脱敏消息，按任务记录排查 |

图谱失败、过期、空图或过滤旁路可以通过 `warnings` 表达，不一定使整个检索请求
失败。`ragflow:graph` 路线、`native_graph_read_v1` 模式及
`native_graph_structural_navigation` 等警告的含义见
[原生图谱诊断](../../docs/NATIVE_GRAPHRAG.md#5-检索来源与缓存边界)。
官方 Graph Read 在 256 节点/128 边处截取且不标记完整性，因此达到任一阈值即降级；
客户端仅接受最多 255 节点/127 边并通过结构校验的响应，流式正文上限为 4 MiB。
删除原文后上游复用旧子图产生的失效来源同样必须触发边界阻断，不能因任务完成而
放宽 `RAG-GRAPH-004`；安全清理旧图的前置条件见原生图谱说明。

## 3. 验收边界

图谱默认关闭；测试错误分支使用合成输入与 Mock，串行并发 `1`。不得为临时 Kimi K3
变更专用 Token 参数来掩盖通用协议问题。四组最小真实 API 请求通过不等于原生构建、
取消和检索引用完整流程已通过；没有证据的真实恢复能力必须保留为待验收。
